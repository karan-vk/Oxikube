# Domain glossary (CONTEXT.md)

Shared vocabulary. Type names in code match these terms; if you need a new term, add it here first.

How to read the **Lives in** column:

- A path under `oxikube_domain` or `oxikube_ports` names a module that exists today. The
  `tests/glossary.rs` test in `oxikube_testkit` fails when such a module is renamed or removed.
- `oxikube_testkit` paths exist today.
- Paths in `oxikube_app`, adapters, `platform` and `ui` crates, and anything marked *(planned)*, are
  the agreed home of a term whose owning epic has not landed yet. Do not invent a different home;
  change this table in the same PR that moves it.

## Identity and resources

| Term | Meaning | Lives in |
|---|---|---|
| **ClusterId** | Stable identifier for a cluster entry in the catalog (hash of kubeconfig source + context name). | `oxikube_domain::ids` |
| **ContextName** | A kubeconfig context name. | `oxikube_domain::ids` |
| **Gvk / Gvr** | Group-Version-Kind / Group-Version-Resource. | `oxikube_domain::ids` |
| **Scope** | Whether a kind is `Namespaced` or `Cluster` scoped. | `oxikube_domain::ids` |
| **ResourceRef** | `{cluster, gvk, namespace, name}` — the address of one object. | `oxikube_domain::ids` |
| **ResourceKind** | Discovery record for one served kind: `Gvk`, plural/singular names, short names, categories, `VerbSet` of supported `Verb`s, namespaced flag, preferred version. Filled by API discovery, read by tables, palette and sidebar. | `oxikube_domain::kinds` |
| **Resource** | Thin model: `ObjectMeta` (with `OwnerRef`s) + the object's JSON as a compact **JsonDoc**, read in place (`Resource::json()`, `get`, `get_str`; `to_value()` only on cold paths). The domain never depends on k8s-openapi. A metadata-only object (from a metadata feed) is **partial** (`Resource::is_partial`): no `spec`/`status`/data, never to be rendered as complete; `KubeResources::upgrade` fetches the full one. | `oxikube_domain::resource` |
| **JsonDoc / JsonRef** | A Kubernetes object's JSON held as one immutable byte buffer (tagged, varint, common keys as small numbers), shared between clones. `JsonRef` is a borrowed, `Copy` view of one value inside it with the read half of `serde_json::Value` (`get`, `pointer`, `as_str`, `as_array`, ...); it never allocates. `to_value()` builds a full `Value` tree for the few cold paths that need one. | `oxikube_domain::json` |
| **View-model** | Typed projection built from `Resource` JSON for a core kind (`PodSummary` with `ContainerSummary`, `NodeSummary`, `WorkloadSummary`, `JobSummary`, `CronJobSummary`). | `oxikube_domain::view` |
| **Trigger (CronJob)** | Run a CronJob now (`cronjob::Trigger`): a Job is created from `spec.jobTemplate` with a server-generated name `<cronjob>-manual-xxxxx`, the `cronjob.kubernetes.io/instantiate: manual` annotation and the CronJob as its owner, as `kubectl create job --from=cronjob/x` does. **Suspend / Resume** set `spec.suspend` on a CronJob (no new Jobs) or a Job (its running pods are deleted until resumed; a finished Job cannot be resumed). All are risk `low` mutations. | `oxikube_app::workloads` |
| **Evict / Force delete / Sanitize (pods)** | `pod::Evict` removes a pod through the eviction subresource, so a PodDisruptionBudget can refuse it ("blocked by disruption budget <name>"); `pod::Delete` deletes it with its own grace period; `pod::ForceDelete` (k9s kill, `ctrl-k`) deletes it with grace period 0, which takes the API object away without waiting for the kubelet. Tiers: evict and delete `Medium` (a simple confirmation naming the pod and cluster; "medium (name)" in the stories means exactly this), force delete `High` (the pod's name typed); a `pod::Delete` with grace 0 is `High` too. **Sanitize** (`pod::Sanitize`, `z`) deletes the Completed (`Succeeded`) and `Failed` pods of a view: one command and one confirmation with the count, one audit record for the command and one per pod, all carrying `batch=<id>`. | `oxikube_app::workloads` |
| **Pod panel** | The detail panel of a pod (`PodPanel`): action bar, the containers table, owner chain, node link, environment (ConfigMap and Secret references resolved on demand, Secret values masked and revealed per variable, in memory only), mounts, probes, volumes, tolerations and affinity. Its data is the domain's `PodDetail`. | `oxikube_resources_ui::kinds::pods::panel`, `oxikube_domain::view` |
| **PodSummary / ContainerSummary** | A pod's table row (READY, STATUS and RESTARTS by kubectl v1.36's pod printer, IP, node, QoS, service account, controller, the pod's effective requests and limits as `ComputeResources`) and one container of it (init / sidecar / regular / ephemeral, state, restarts, `Probes`, `ContainerPort`s, requests and limits): the pods table and the containers drill-down. | `oxikube_domain::view` (E12-S02) |
| **Quantity** | A Kubernetes resource quantity (`500m`, `128Mi`) parsed into an exact decimal (`i128` mantissa × 10^exponent, nano precision), printed like apimachinery `Quantity.String()`. | `oxikube_domain::quantity` |
| **Age** | A non-negative span since a resource was created, formatted `kubectl`-style (`AgeStyle::Kubectl`) or kdash-style (`AgeStyle::Detailed`). | `oxikube_domain::age` |
| **LogLine** | One line of container output with its kubelet timestamp; over-long lines are cut and flagged. | `oxikube_domain::log` |
| **Detail drawer / DetailView** | The generic detail of one object (header with status chip, labels and annotations with copy, owner links, finalizers, conditions, `status` summary, Events). One entity with two mounting modes: the right-dock `DetailDrawer` of a cluster tab, or, pinned, a workspace tab. A Secret shows its key names, sizes and its type's public facts by default and a value only after **Reveal**. | `oxikube_resources_ui::detail` |
| **CRD browsing / CrdInfo / SchemaTree** | Browsing custom resources: the sidebar's Custom Resources groups (kinds per API group from discovery), the CRD list, the table of a CRD's custom resources on the Table feed (printer columns), its version switcher, and the Schema tab of a CRD's detail. `CrdInfo` is a CRD read for browsing (group, kind, scope, names, versions, the version a table opens); `SchemaTree` is its `openAPIV3Schema` as a lazily built, bounded, collapsible tree. **CrdSummary** (E12-S17) is the CRD's typed view-model (names, versions with their **printer columns** split by priority into default and wide, conversion, conditions) behind the CRD list's Versions / Aliases cells and the definition panel of its detail. | `oxikube_resources_ui::crds`, `oxikube_domain::view::CrdSummary`, `oxikube_resources_ui::kinds::crd` |
| **Event** | A Kubernetes Event (`EventType` Normal/Warning, reason, message, the `regarding` object). | `oxikube_domain::event` |
| **MetricsSample** | One CPU and memory reading for a node, pod or container (`MetricsSubject`); an absent value is `Reading::Missing` with a `MissingReason` (`NotInstalled` 404, `ApiUnavailable` 503, `Forbidden` 403, `NotYetAvailable`, `Other`). A pod sample keeps one `ContainerUsage` per container beside its total. `MetricsPort` answers `MetricsOutcome::{Available, Unavailable(reason)}`: absence is a state, never an error. | `oxikube_domain::metrics` |
| **ResourceAmounts / PodResources / Utilisation** | `ResourceAmounts` is CPU and memory as exact `Quantity` values plus whole-number GPU counts keyed by vendor resource name (`metrics.gpu_vendors`). `PodResources` is a pod's effective requests and limits (Kubernetes rule: containers plus sidecars, or the init-container peak, plus overhead). `Utilisation` is the four pod-table ratios `%CPU/R`, `%CPU/L`, `%MEM/R`, `%MEM/L`; `None` is a dash (no reading, request or limit), never `0`. Node and namespace sums (`NodeAllocation`, `NamespaceAllocation`) skip terminated pods; unscheduled pods count for the namespace only. | `oxikube_domain::utilisation`, `oxikube_app::metrics` |
| **MetricsService / ClusterUsage / MetricsState / UsageThresholds** | Live usage from metrics-server (E13-S03). The `MetricsService` polls a cluster only while a consumer holds a `MetricsInterest` for a `MetricsKind` (Nodes, Pods), a window shows its tab (`MetricsVisibility`) and it is connected; the `Cadence` is the interval (15 s), backoff on errors, rarely while absent. Each cluster's `ClusterUsage` keeps the latest reading and a 60-sample `SampleRing` per node and pod (the columns' source); `MetricsState` per kind is `Idle`, `Loading`, `Available`, `Unavailable(reason)` or `Failed`, shown as `metrics unavailable: <reason>`, never as a zero. `UsageThresholds` (k9s' `thresholds`, the `metrics.thresholds` setting) tone the `%` of a limit or of a node's allocatable amber and red. | `oxikube_app::metrics::live`, `oxikube_resources_ui::metrics` |

## Errors

| Term | Meaning | Lives in |
|---|---|---|
| **OxiError / OxiResult** | The error every port returns: `{kind, message, source, retryable}`. Branch on `kind()` and `is_retryable()`, never on the message. | `oxikube_domain::error` |
| **ErrorKind** | `Auth`, `Forbidden`, `NotFound`, `Conflict`, `Network`, `Timeout`, `Validation`, `Unsupported`, `Internal`, `BudgetExceeded` (the watch budget refused a new feed). Adapter mapping rules are in `docs/ARCHITECTURE.md`. | `oxikube_domain::error` |
| **Redaction** | Removing tokens and Secret data from text before it is logged, audited or put in an error. `oxikube_domain::redact` holds the pure scrubber (`redact(&str) -> Cow<str>`, `Redacted<T>`); adapters redact before building an error and `oxikube_logging` scrubs every log line with it. | `oxikube_domain::redact` |

## Sessions and state

| Term | Meaning | Lives in |
|---|---|---|
| **ClusterSession** | One open cluster: its `ClusterId` and context, `ClusterSessionState`, the `ClusterPorts` bundle while connected, `Capabilities`, `NamespaceSelection`, read-only flag and `ClusterColour`. One workspace tab per session. Owned by the **ClusterSessionManager** (connect / disconnect / reconnect, `SessionUpdate` stream); `ClusterSession` is a snapshot of it that hands out the read half of the resource port only. | `oxikube_app::session` |
| **ClusterConnectorPort / ClusterPorts** | The port that turns a context into a live connection, and the per-connection bundle it returns (resources, discovery, tables, logs, exec, port-forward, metrics, `AccessReviewPort`). The adapter reports health through a `HealthReporter` (`HealthSignal`: `Healthy`, `Unhealthy`, `Failed` with the failure's `ErrorKind` and retry flag, which decide between automatic reconnect, `AuthRequired` and `Error`); dropping the `ClusterConnection` tears its feeds and probe loop down. `ExecInteractivity` is the per-cluster exec-plugin policy passed with each connect. | `oxikube_ports::{connector, access}` |
| **SessionUpdate** | One change to one session (`Opened`, `StateChanged`, `CapabilitiesChanged`, `NamespaceChanged`, `ReadOnlyChanged`, `ColourChanged`, `Closed`), tagged with its `ClusterId`, on a bounded broadcast; a slow subscriber gets `SessionLagged` and re-reads. Not to be confused with `SessionEvent`, the state machine's input. | `oxikube_app::session` |
| **Catalog / CatalogEntry** | The list of every kubeconfig context Oxikube knows (the home screen). A `CatalogEntry` is one `ClusterContext` of the `ClusterSourcePort` (name, kubeconfig cluster and user names, source file, an optional `problem` when it names something the kubeconfig lacks) plus the user's marks: favourite and last-used time, kept in the `cluster_catalog` state table. Ordered favourites, then last used, then name. Reading it never touches a cluster. | `oxikube_app::catalog` |
| **ClusterColour** | A cluster's accent colour, sRGB written `#rrggbb` (hotbar dot, tab stripe, badges). | `oxikube_domain::colour` |
| **ClusterSessionState** | `Disconnected → Connecting → (AuthRequired) → Ready ↔ Degraded → Error`; a connected session whose credentials are rejected for good goes to `AuthRequired`, and `Error` recovers only through `Connect` (which **AutoReconnect** sends after a transient failure). Advanced by `SessionEvent`s; `SessionPhase` is the payload-free discriminant; a bad pair is an `InvalidTransition`. | `oxikube_domain::session` |
| **AutoReconnect** | The reconnect the session manager makes by itself after the connection failed for a transient reason (a `Network`, `Timeout` or retryable `Auth` health `Failed`): capped exponential backoff on the `ClockPort` (1 s doubling to 30 s by default), until `Ready`, `AuthRequired`, a permanent failure or a user action. `ClusterSession::auto_reconnect` gives the next attempt and its delay; the connect view's error card says "Reconnecting automatically". | `oxikube_app::session` |
| **ConnectView / ConnectViewModel** | What a cluster tab shows while its session is not `Ready`: a spinner with the server for `Connecting`, the plugin's message with the cluster's exec policy and Retry for `AuthRequired`, a summary with expandable details for `Error` (headed "Lost the connection" with a "Reconnecting automatically" line while an **AutoReconnect** is planned), and (as a banner over the content, not instead of it) "some data may be stale" for `Degraded`. `ConnectViewModel::of(state, info)` is the pure mapping; every text in it is redacted. Retry is `cluster::Reconnect`, Cancel is `cluster::CancelConnect`. | `oxikube_catalog_ui::connect` |
| **HumanError** | An error as the user reads it: one plain sentence (`summary`, chosen from what the message says and else from its `ErrorKind`; never the `internal error:` label) and the redacted `raw` text behind a Details toggle. Built from an `OxiError`, a kind and message, or a rendered error string. Shared by the connect view, the log viewer and the terminal. | `oxikube_domain::human_error` |
| **ExecPolicy** | The per-cluster `exec_interactivity` setting as the connect view words it: *Forbid* (`never`: a credential plugin may not prompt), *Ask* (`if_available`: it may use a terminal when one exists), *Allow* (`always`). Its line is shown next to `AuthRequired` only for *Forbid*, in plain words. | `oxikube_catalog_ui::connect` |
| **NamespaceSelection** | `All` or a `Set` of namespaces chosen in the UI. `NamespaceFavourites` is the user's pinned list. | `oxikube_domain::session` |
| **WatchScope** | Derived from a `NamespaceSelection` and a kind's `Scope`: `Cluster` or `Namespaces`; decides whether feeds are cluster- or namespace-scoped. | `oxikube_domain::session` |
| **NamespaceService** | Sets a session's `NamespaceSelection` and remembers it per cluster with the favourites and the namespace names the user typed (`NamespacePrefs`, `StatePort` kv `cluster/<id>/namespaces`, never settings). Lists namespaces for the selector; when the cluster answers `Forbidden` the list is the typed names (`NamespaceSource`). Runs the `namespace::Select` and `namespace::ToggleFavourite` commands. An empty selection is `All`; `0`-`9` select All or the first nine favourites. | `oxikube_app::session::namespaces` |
| **ScopeDelta** | What changes between two `WatchScope`s of a kind: namespaces whose feed starts, stops or stays, and whether the cluster-wide feed starts or stops. `{a, b}` to `{b, c}` starts `c`, stops `a`, keeps `b`. The `ResourceStore` re-scopes from it. | `oxikube_app::session::namespaces` |
| **NamespaceSelector** | The namespace dropdown of one cluster tab: trigger, search box, virtualised list of All / favourites / namespaces, digit keys. A view over the `NamespaceService`; it never opens feeds. | `oxikube_catalog_ui::namespaces` |
| **Namespace use / favourite slot** | "Use this namespace" (k9s `u`) is `namespace::Select` with that one name. A **favourite slot** is a digit: `0` is All, `1`-`9` the nth favourite (`namespace::UseFavourite`, bound in every resource table; `p` pins the namespace under the cursor on the Namespaces table). Favourites are per cluster in the `NamespaceService`'s prefs, never settings. | `oxikube_app::session::namespaces`, `oxikube_resources_ui::table::namespaces` (E12-S16) |
| **Protected namespace** | `kube-system`, `kube-public`, `kube-node-lease`, `default`: deleting one takes the same typed name as any namespace plus a **DeleteNote** of `Danger` level saying what breaks. | `oxikube_domain::view` (`protected_reason`, E12-S16) |
| **NamespaceSummary / DeleteNote** | The typed view of a Namespace (phase `Active` / `Terminating`, finalizers, the controller's blocking conditions, **HNC** markers: the `hnc.x-k8s.io/subnamespace-of` annotation, the `<ancestor>.tree.hnc.x-k8s.io/depth` labels) and the lines the delete dialog shows before the name is typed (`delete_notes`: protected, HNC parent or child, already terminating, what the namespace holds), most severe first. `namespace::Delete` carries the counts into its audit record. | `oxikube_domain::view`, `oxikube_app::namespaces` (E12-S16) |
| **Pod count (Namespaces table)** | The Pods column reads the pods feed's per-namespace index (`ResourceStore::count_in_namespace`, O(1)); `–` when no open, listed feed covers the namespace. The table leases the pods and deployments feeds while it is open. | `oxikube_app::namespaces::NamespaceColumns` (E12-S16) |
| **Feed** | A live stream of `DeltaBatch`es for one (cluster, gvk, scope): reflector, metadata-only, or Table API. Typed as `WatchFeed`. | `oxikube_ports::feed`; producers in `oxikube_kube::feed` (reflector and metadata-only variant: `ReflectorFeed`, E04-S02/S03) |
| **Watch budget / FeedStats** | Per-cluster limits on feeds (`max_feeds`) and held objects (`max_objects`), the idle grace period after which an unobserved feed is torn down, and the degrade of full feeds to metadata-only above `metadata_above` objects. `FeedRegistry` hands out `FeedLease`s (one per subscriber) and `SelectionLease`s (one feed per selected namespace); `FeedStats` is its counter snapshot (feeds, objects, events, restarts, bytes), `FeedVariant` what a feed carries (`Full`, `Metadata`, `Table`). An **owned feed** is one port call's feed (`open_owned`): budgeted and counted, never shared, gone with its stream. The limits are the per-cluster `watch_budget` setting (`WatchBudgetPrefs`). | `oxikube_ports::feed_stats`, `oxikube_ports::cluster_prefs`; registry `oxikube_kube::budget` (E04-S13, E04-F543) |
| **FeedState** | Health of one feed: `Warming` (listing or relisting), `Live`, `Retrying` (backing off after a watch error), `Stopped`. Lets the session go `Degraded` while a feed retries. | `oxikube_kube::feed` |
| **Jump bar / JumpCommand / JumpPlan** | The `:` command line (k9s's fastest habit): `:<alias> [ns] [/filter] [k=v,..] [@ctx]`, `:ctx [name]`, `:ns [name]`, `:q`, and `-` `[` `]` for the history. A line is **parsed** into a `JumpCommand` (syntax only, with spans to underline) and **planned** against the shown cluster into a `JumpPlan`: the navigation `Command`s that do it, sent through the `CommandBus` like any click. The **jump history** is the session's ring of lines run: `[` back, `]` forward, `-` the previous view and back again. A jump to a context whose session is not open connects first and does the rest once it is up. | `oxikube_app::search::jump`, `oxikube_palette::jump` |
| **Picker / PickerDelegate** | A query field over a virtualised list of matches (`Picker<D>`), Zed's picker design: the picker owns the field, the list, the selection keys (`picker::SelectNext` .. `picker::Cancel` in the `Picker` key context), confirm and dismissal; the `PickerDelegate` owns the data, filters it for a query (`update_matches`, off the UI thread for large lists), renders one match and decides what confirming does. The command palette, the `:` jump bar's completions and the container chooser are delegates. | `oxikube_palette::picker` |
| **Command palette / PaletteHost / CommandSurface** | The searchable list of every registered command (E11-S03): `CommandPalette` is a modal over a `Picker`, opened by `palette::Toggle` (`cmd-shift-p`), listing the commands that can run where the user is (unavailable ones hidden, or dimmed with the reason under "Show all"), each with its category, title and key binding, recents first. A `PaletteHost` per window captures the focused view's `CommandSurface` (a table or the detail drawer: its view kind, cluster, kind and selected objects) and the session, and sends the confirmed command through the `CommandDispatcher` once the palette has closed and given the focus back. `commands_for` turns the listed id into the `Command`s to dispatch; `RecentsStore` remembers the ids run lately. | `oxikube_palette::command_palette`, `oxikube_workspace::command_surface`, `oxikube_app::command_bus::{invoke, recents}` |
| **Help overlay / HelpEntry** | The `?` modal (E11-S10): the keys that work where the focus is, grouped by command category (`Navigation` for keys that run no command), searchable by title, category, keystroke or action name, with a chip on bindings from the user's `keymap.json` (`User`) or the vim base (`Base`) and on defaults the user unbound (`Unbound by you`). It is built from the keymap's own dispatch rules applied to the focus path when it opens, lists keys and runs nothing; with no focused view it lists every binding. `help::Show` is its command. | `oxikube_palette::help` |
| **Row action** | A command a resource table offers for an object (context menu, palette, key): a `RowActionSpec` (command, kinds, how an object becomes the command, bulk or not) registered in a `RowActionRegistry` and resolved against the `CommandBus` registry and the session's capabilities and read-only flag (`RowActions::actions_for` / `resolve`). Delete is the first; per-kind ones come with E12. | `oxikube_app::actions` |
| **Delete flow** | `DeleteFlow`: plans (`DeletePlan`) and runs a delete of one object or a selection. Each object is its own guarded `resource::Delete` (read-only check, confirmation tier by target, server dry run, audit with `Initiator::Ui`); one failure does not stop the rest and every object gets an `ItemStatus` (deleted, deleting, forbidden, not found, failed). Type-the-name is the object's name for one object and the cluster's context name for a selection. | `oxikube_app::actions` |
| **Delta / DeltaBatch** | One change in a feed (`Applied`, `Deleted`, `Restarted`) and a coalesced batch of them. Lives in ports, not the domain: it is transport. | `oxikube_ports::feed` |
| **Table / TableFeed** | Server-side Table API data (kubectl-identical columns incl. CRD printer columns) as `TableColumn`s and `TableRow`s. | `oxikube_ports::table`; producer `oxikube_kube::table` |
| **Drain** | Emptying a node of its pods like `kubectl drain`: plan (which pods are evicted, skipped as DaemonSet or mirror pods, or block the drain), cordon, evict with retry while a PodDisruptionBudget refuses, wait for each pod to go. Runs as a stream of `DrainProgress` and ends in a `DrainSummary`; configured by `DrainOptions`, chosen as **DrainFlags** (the `kubectl drain` flags: `ignore_daemonsets` on by default, `delete_emptydir_data`, `force`, grace period, timeout 5 min). The algorithm is the adapter's (`KubeDrain` behind the `DrainPort`); `node::Drain` (E12-S10) runs it through the guard: risk **High** (the node's name typed; blocked read-only), the plan shown before anything changes, one audit record for the drain plus one per pod sharing a **batch** id, cancel by dropping the dispatch (the node stays cordoned). Key `r` on the Nodes table. | `oxikube_domain::drain`, `oxikube_kube::algorithms`, `oxikube_app::nodes` |
| **RolloutRevision** | One entry of a Deployment's rollout history: the revision number, the ReplicaSet that holds its template, the change cause and the images. `rollout undo` restores the template of one. | `oxikube_kube::algorithms` |
| **Revision / RollbackPlan / RolloutService** | A **Revision** (`oxikube_domain::rollout`, E12-S06) is one row of a workload's rollout history: the number, the ReplicaSet (Deployment) or ControllerRevision (StatefulSet, DaemonSet) that holds it, the change cause, images, a ReplicaSet's ready/desired, age, whether it is running and how it differs from the running template. A **RollbackPlan** is `kubectl rollout undo` worked out from the objects: the revisions it goes from and to and the patch (a JSON patch replacing `spec.template` for a Deployment, a ControllerRevision's `data` as a strategic merge patch for the others) or `AlreadyCurrent`. **RolloutService** (`oxikube_app::rollout`) reads the history on demand and runs `workload::Rollback` under the guard: **medium** risk, one simple confirmation, a server dry run first, blocked read-only, audited with the revisions. A paused Deployment is refused. | `oxikube_domain::rollout`, `oxikube_app::rollout` |
| **TableSource** | Whether a `Table`'s columns are the server's (`Server`) or the adapter's plain-JSON fallback (`Objects`, the server ignored the Table `Accept` header). | `oxikube_ports::table` |
| **ResourceStore** | App-side cache over one cluster session's feeds, keyed by (gvk, `FeedScope`), with sort/filter/index (name, namespace, label) and ref-counted subscriptions; the last subscriber's drop starts a grace period after which the feed is aborted. `ResourceStores` keeps one per connected session. | `oxikube_app::store` (E07-S01) |
| **Cluster overview / OverviewSnapshot** | A cluster tab's landing page (E13-S09): health tiles, capacity and allocation (requests, limits and live usage against the nodes' allocatable), top consumers, recent warnings, cluster info, history graphs with Prometheus. Its numbers are an `OverviewSnapshot` that `OverviewFeed` publishes from incremental tallies (`PodTally`, `NodeTally`) and the live metrics, off the UI thread. | `oxikube_app::cluster_overview`, `oxikube_overview_ui` |
| **Distribution** | The Kubernetes distribution a cluster runs (EKS, GKE, AKS, OpenShift, k3s, kind, ...), guessed from evidence only that distribution leaves (version suffix, node labels, `providerID`); `unknown` otherwise. | `oxikube_app::cluster_overview::detect_distribution` |
| **CountState / CountsLease** | What the `ResourceStore` says about a kind's count (`Counted` with total and healthy, `Loading`, `NoAccess`, `OverBudget`, `Failed`, `NotWatched`). `ResourceStore::counts` only reads the caches' running tallies and starts no feed; a `CountsLease` keeps the feeds a view needs open through the normal subscribe path (so the watch budget decides). Health is `oxikube_domain::view::health_of`. | `oxikube_app::store::counts` (E07-S11) |
| **FeedScope** | The part of a `WatchScope` one feed covers: `Cluster` or one `Namespace`. A multi-namespace selection is served by one feed per namespace, so a namespace that stays selected keeps its feed. | `oxikube_app::store` |
| **ConfigPanel / Panel** | The kind's own panel above a detail's Overview for the Config section's smaller kinds (E12-S12): a `Panel` is plain data (sections of pair, bar, link, table and code rows) built from a domain view-model (`QuotaSummary`, `HpaSummary`, `PdbSummary`, `WebhookConfigSummary`, ...), drawn by one renderer. A quota's bars show `status.used` against `status.hard` per resource; a webhook configuration shows its `caBundle` as `Present` or `Absent`. | `oxikube_resources_ui::kinds::config`, `oxikube_domain::view::config` |
| **FeedPolicy / FeedKind** | Which feed serves a kind (ADR 0006): `Full` reflector for core kinds, `Metadata` for bulky or sensitive ones (Secrets, ConfigMaps; Leases are read in full for their holder, E12-S12), `Table` for CRDs and unknown kinds. Table-driven, with per-kind overrides. | `oxikube_app::store` |
| **FeedBudget** | The hook a watch budget implements: `admit` (grant, degrade to a cheaper `FeedKind`, refuse) before the store opens a feed, `released` after it stops one, `refused` when the store gives one up, and optionally the `idle_grace` the store keeps a released feed. A refusal first evicts idle feeds. In the app it is the cluster's `FeedRegistry` (`RegistryBudget`). | `oxikube_app::store` |
| **StoreDelta / RowOp** | One item of a `Subscription` stream: the rows' change (a `Snapshot`, or coalesced `RowOp`s `Insert`/`Update`/`Remove` with positions in the subscriber's sorted list), the `FeedState` (`Warming`, `Ready`, `Retrying`, `Forbidden`, `Unauthorized`, `Failed`) and the Table columns when they change. Distinct from the transport `Delta` of `oxikube_ports::feed`. | `oxikube_app::store` |
| **ColumnProvider** | The one trait a table asks for a kind's `Column`s and an object's `Cell` in a column; `CoreColumns` (our catalogue of ~40 core kinds) and `TableColumns` (the server's Table columns) implement it. Cheap, synchronous, memoised per (kind, capabilities). | `oxikube_app::columns` (E07-S02) |

## Commands and safety

| Term | Meaning | Lives in |
|---|---|---|
| **Command** | A user/agent action: the `Command` payload enum, identified by a `CommandId` (`workload::Scale`) and described by `CommandMeta` (title, `CommandScope`, mutating, confirm tier, capabilities). Dispatched through the **CommandBus** (`CommandBus::dispatch(cmd, DispatchContext)`; handlers registered per crate into a `CommandRegistry`, each with its MCP tool stub). The id is also the keymap action and the MCP tool name. | `oxikube_domain::command`; bus in `oxikube_app::command_bus` |
| **Command availability / CommandContext / CommandInfo** | Where a command can run, as data (E11-S01): `CommandMeta` carries a `category` (from the id's namespace), `keymap_action()` (the id) and an `Availability` (`views`, a `SelectionKind` of none / one / many / of-kind, `requires_writable`, which every mutation sets). `CommandBus::list(&CommandContext)` returns the registered commands that can run for the focused `ViewContext`, the session's capabilities and read-only flag, and the `Selection`, as `CommandInfo`s in category-then-title order; a mutation is hidden on a read-only session, `CommandBus::all()` plus `CommandInfo::check` give the "show all" list with the reason (`Unavailable`). The palette, help overlay and keymap read this; the `MutationGuard` still decides at dispatch. | `oxikube_domain::command::availability`, `oxikube_app::command_bus::{availability, index}` |
| **Immediate command** | A command whose handler changes only UI or session state in memory (the cluster tab commands, `namespace::Select`), registered with `CommandRegistry::register_immediate`. The UI runs it inside the update that took the input (`CommandBus::dispatch_now`, through `ClusterCommandRunner`), so the next frame shows it; the I/O that completes it (`Immediate::rest`, a state store write) runs off the UI thread. Every other caller dispatches it as usual and awaits the rest. Never a mutation, exec, privileged or posture command. The session updates it makes reach the views in that update through the **SessionEcho**. | `oxikube_app::command_bus::immediate`; runner and `SessionEcho` in `oxikube_workspace::cluster` |
| **Capability** | A flag for what a session/backend can do (mutate, exec, logs, portforward, helm, argo…). `Capabilities` is the set. | `oxikube_domain::command` |
| **MutationGuard** | The single pipeline every mutation passes: read-only check → confirmation tier → dry-run → execute → audit. It alone holds a `ResourceWriter` and hands it to a handler only inside a **Mutation** permit. A confirmation is a round trip: `Outcome::NeedsConfirmation` with a single-use `ConfirmationToken`, then a second dispatch carrying the `Confirmation`. Failing to audit fails the mutation closed. The writer inside a **Mutation** re-reads the read-only flag before every request, so a flow that outlives admission still stops. | `oxikube_app::guard`, `oxikube_app::audit` |
| **Risk / ConfirmTier** | Stories say "confirm low / medium / high". Mapping: **Low** → `Simple` (one-click confirm; may be skipped per session by setting), **Medium** → `Simple` naming the target and cluster, **High** → `TypeName`, **Irreversible** → `TypeName` + mandatory server dry-run diff. Reads never confirm. A read-only cluster refuses every tier before any request and records `AuditOutcome::Denied`; the guard returns the typed `DispatchError::ReadOnly { cluster, context }`, which maps to `ErrorKind::Forbidden` (`ErrorKind` has no `ReadOnly` variant). | `oxikube_domain::safety` |
| **Initiator** | `Ui / Command / Agent / Plugin` — who asked for a mutation. Defined in `safety`, re-exported from `audit`. | `oxikube_domain::safety` |
| **AuditRecord** | Who/what/where/when/outcome/initiator for a mutation (`AuditOutcome`: Succeeded, Failed, Denied, Cancelled). Never holds request bodies. Stored in SQLite through `StatePort`. | `oxikube_domain::audit` |

## Ports

## Workspace shell, settings and testing

| Term | Meaning | Lives in |
|---|---|---|
| **Item / Panel / Pane / Dock** | Workspace shell concepts (Zed design): an **Item** is the content of a centre tab (title, icon, dirty; may refuse to close); a **Panel** is a dockable side view; a **Pane** is a tab strip of items, and the **PaneGroup** the tree of horizontal/vertical splits of panes in the centre; a **Dock** is the left, bottom or right edge area holding panels. Closed items are kept as descriptors (kind + state), not live entities, so they can be reopened. | `oxikube_workspace` |
| **Layout persistence** | Saving the workspace's layout (dock sizes and visibility, the split and tab tree, the open item descriptors `{ kind, state }`, the active pane, the window place) as a versioned `SerializedWorkspace` row in the `StatePort` table `workspace_layout`, one per window id, and restoring it on launch through the `ItemRegistry`. Unknown item kinds are skipped. A corrupt state database is moved aside and replaced; settings and keymap files are never touched. Never holds secrets. | `oxikube_workspace::persistence`, `oxikube_state_sqlite` |
| **ClusterTab / ClusterTabs** | The workspace tab of one cluster session: an `Item` hosting a `Workspace` of its own (its sidebar dock, its pane group, its layout saved per cluster id), shown with the cluster's colour dot. | **Session restore / RestorePlan / placeholder tab** | Reopening the last session at launch (`session.restore`, default off): the clusters that had tabs, in order, the displayed one, and each cluster's namespace selection. A **RestorePlan** is the saved session matched against today's catalog (clusters to reopen, the displayed one, the `dropped` ones that no kubeconfig defines any more). A **placeholder tab** is a restored cluster's tab while its session is still `Disconnected`: it stays until the cluster connects (the displayed one at launch, the others when their tab is first shown, or all with `session.restore_connect = "all"`). A cluster that fails shows `Error` in its own tab and affects no other. | `oxikube_app::session::restore`, `oxikube_workspace::cluster_tab` |
| **Sidebar / SidebarSection** | The cluster's map in the left dock of its tab: collapsible **SidebarSection**s (Cluster, Nodes, Workloads, Config, Network, Storage, Namespaces, Events, Helm, Access Control, Custom Resources) of entries, registered with the **SidebarRegistry** (a feature's `init(cx)`), not hard-coded. Open and closed groups are saved per cluster. | `oxikube_workspace::sidebar` |
| **AccessRules / Access** | A rules review (`SelfSubjectRulesReview`) as plain data: allow rules plus a `partial` flag. `level(verb, group, resource)` answers **Access**: `Granted`, `Restricted` (named objects only), `Unknown` (partial review) or `Denied`; only `Denied` hides anything. | **Hotbar** | The strip at the window's left edge with a tile (initials, colour dot, state dot) for every connected or favourite cluster, in the user's order. Clicking shows the cluster's tab or connects the favourite. | `oxikube_catalog_ui::hotbar` |
| **Status bar / StatusItem** | The strip under the docks with a left and a right group. Items notify themselves; the bar never redraws on its own. | `oxikube_workspace::status_bar` |
| **Modal layer / ModalView** | The overlay that hosts one **ModalView** at a time over the whole workspace (a second modal replaces the first). | **Toast / ToastLayer** | A transient message in the bottom-right corner: a level, a message, optional actions, a dedup key and a timeout (errors stay). | **Main window / Root** | The OS window opened by `oxikube_workspace::window`: native title bar on macOS, client-side decorations on Linux; its root view is `oxikube_ui`'s `Root`, which renders the dialog, sheet and notification layers once above the workspace content. | `oxikube_workspace::window`, `oxikube_ui::root` |
| **Quit guard / running operation** | A **running operation** is something quitting would stop (an exec session, a port-forward, an apply). | **UI zoom / reduce-motion** | UI zoom is the `ui_scale` factor (0.5 to 3.0) behind `u(px)` and the window's rem size, changed by `view::ZoomIn`/`ZoomOut`/`ZoomReset` and persisted in `settings.json`. | **Alias / AliasTable / AliasTarget** | A word the `:` jump bar understands (`po`, `deploy`, `certs`, a user's `prodpods`) and what it stands for: an **AliasTarget**, either a `Gvr` (open that resource's list) or a `Command { name, args }` (a jump-bar command line, k9s's `fred: pod fred app=blee`). An **AliasTable** (one per cluster) merges three layers, highest first: the **user** layer (`aliases.json`), the **built-in** k9s names, and **discovery** (plural, singular, short names, Kind and `plural.group` of what the cluster serves). `resolve(word)` gives `Exact`, `Ambiguous` (several served types claim the word; candidates in a fixed order) or `Unknown` with suggestions. The score is nucleo's plus small named boosts for an exact match, a prefix match and a recent candidate (`search::fuzzy::score`). **Highlight** turns the positions into matched byte ranges for a view (`highlight::matched_ranges`). | **StateRecents / JumpRecents** | Recents that survive a restart (E11-S11), through `StatePort`: **StateRecents** is the `RecentsStore` of command ids the palette ran lately (global, 50), **JumpRecents** the lines typed into the `:` bar per `ClusterId` (100, deduplicated by text, never a line that looks like a secret). | **Settings layer** | `default.json → user settings.json → clusters.<id>` overrides. | `oxikube_settings` |
| **ClusterPreset** | A named safety posture a user gives a cluster in one step: **prod** (red, read-only on), **staging** (amber), **dev** (green), **none**. | **Read-only badge / ClusterMark** | What a cluster looks like at a glance: its colour dot and, when read-only, a lock, drawn the same on its tab, hotbar entry and status bar item. | **ClusterSettings / ClusterPrefs** | The per-cluster settings, resolved field by field through the settings layers: `display_name`, `colour`, `read_only`, `default_namespace`, `terminal_cwd`, `node_shell_image` / `node_shell_pull_secret`, `exec_in_read_only` (whether a shell may open on a read-only cluster, default no), `prometheus` (`enabled`, `provider` auto / manual / off, `kind`, service `path` or `url`, `path_prefix`, `auth`, `auth_user`, `auth_secret` naming a keychain entry), `accessible_namespaces`, `exec_interactivity`.
