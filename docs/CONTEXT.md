# Domain glossary (CONTEXT.md)

Shared vocabulary. Type names in code match these terms; if you need a new term, add it here first.

How to read the **Lives in** column:

- A path under `oxikube_domain` or `oxikube_ports` names a module that exists today. The
  `tests/glossary.rs` test in `oxikube_testkit` fails when such a module is renamed or removed.
- `oxikube_testkit` paths exist today.
- Paths in `oxikube_app`, adapters, `platform` and `ui` crates, and anything marked *(planned)*, are
  the agreed home of a term whose owning epic has not landed yet. Do not invent a different home;
  change this table in the same PR that moves it.

## Identity and resources

| Term | Meaning | Lives in |
|---|---|---|
| **ClusterId** | Stable identifier for a cluster entry in the catalog (hash of kubeconfig source + context name). | `oxikube_domain::ids` |
| **ContextName** | A kubeconfig context name. | `oxikube_domain::ids` |
| **Gvk / Gvr** | Group-Version-Kind / Group-Version-Resource. | `oxikube_domain::ids` |
| **Scope** | Whether a kind is `Namespaced` or `Cluster` scoped. | `oxikube_domain::ids` |
| **ResourceRef** | `{cluster, gvk, namespace, name}` — the address of one object. | `oxikube_domain::ids` |
| **ResourceKind** | Discovery record for one served kind: `Gvk`, plural/singular names, short names, categories, `VerbSet` of supported `Verb`s, namespaced flag, preferred version. Filled by API discovery, read by tables, palette and sidebar. | `oxikube_domain::kinds` |
| **Resource** | Thin model: `ObjectMeta` (with `OwnerRef`s) + raw `serde_json::Value`. The domain never depends on k8s-openapi. A metadata-only object (from a metadata feed) is **partial** (`Resource::is_partial`): no `spec`/`status`/data, never to be rendered as complete; `KubeResources::upgrade` fetches the full one. | `oxikube_domain::resource` |
| **View-model** | Typed projection built from `Resource` JSON for a core kind (`PodSummary` with `ContainerSummary`, `NodeSummary`, `WorkloadSummary`, `JobSummary`, `CronJobSummary`). | `oxikube_domain::view` |
| **Quantity** | A Kubernetes resource quantity (`500m`, `128Mi`) parsed into an exact decimal (`i128` mantissa × 10^exponent, nano precision), printed like apimachinery `Quantity.String()`. | `oxikube_domain::quantity` |
| **Age** | A non-negative span since a resource was created, formatted `kubectl`-style (`AgeStyle::Kubectl`) or kdash-style (`AgeStyle::Detailed`). | `oxikube_domain::age` |
| **LogLine** | One line of container output with its kubelet timestamp; over-long lines are cut and flagged. | `oxikube_domain::log` |
| **Detail drawer / DetailView** | The generic detail of one object (header with status chip, labels and annotations with copy, owner links, finalizers, conditions, `status` summary, Events). One entity with two mounting modes: the right-dock `DetailDrawer` of a cluster tab, or, pinned, a workspace tab. Never shows a Secret value, only key names. | `oxikube_resources_ui::detail` |
| **CRD browsing / CrdInfo / SchemaTree** | Browsing custom resources: the sidebar's Custom Resources groups (kinds per API group from discovery), the CRD list, the table of a CRD's custom resources on the Table feed (printer columns), its version switcher, and the Schema tab of a CRD's detail. `CrdInfo` is a CRD read for browsing (group, kind, scope, names, versions, the version a table opens); `SchemaTree` is its `openAPIV3Schema` as a lazily built, bounded, collapsible tree. | `oxikube_resources_ui::crds` |
| **Event** | A Kubernetes Event (`EventType` Normal/Warning, reason, message, the `regarding` object). | `oxikube_domain::event` |
| **MetricsSample** | One CPU and memory reading for a node, pod or container (`MetricsSubject`); an absent value is `Reading::Missing` with a `MissingReason`. | `oxikube_domain::metrics` |

## Errors

| Term | Meaning | Lives in |
|---|---|---|
| **OxiError / OxiResult** | The error every port returns: `{kind, message, source, retryable}`. Branch on `kind()` and `is_retryable()`, never on the message. | `oxikube_domain::error` |
| **ErrorKind** | `Auth`, `Forbidden`, `NotFound`, `Conflict`, `Network`, `Timeout`, `Validation`, `Unsupported`, `Internal`, `BudgetExceeded` (the watch budget refused a new feed). Adapter mapping rules are in `docs/ARCHITECTURE.md`. | `oxikube_domain::error` |
| **Redaction** | Removing tokens and Secret data from text before it is logged, audited or put in an error. `oxikube_domain::redact` holds the pure scrubber (`redact(&str) -> Cow<str>`, `Redacted<T>`); adapters redact before building an error and `oxikube_logging` scrubs every log line with it. | `oxikube_domain::redact` |

## Sessions and state

| Term | Meaning | Lives in |
|---|---|---|
| **ClusterSession** | One open cluster: its `ClusterId` and context, `ClusterSessionState`, the `ClusterPorts` bundle while connected, `Capabilities`, `NamespaceSelection`, read-only flag and `ClusterColour`. One workspace tab per session. Owned by the **ClusterSessionManager** (connect / disconnect / reconnect, `SessionUpdate` stream); `ClusterSession` is a snapshot of it that hands out the read half of the resource port only. | `oxikube_app::session` |
| **ClusterConnectorPort / ClusterPorts** | The port that turns a context into a live connection, and the per-connection bundle it returns (resources, discovery, tables, logs, exec, port-forward, metrics, `AccessReviewPort`). The adapter reports health through a `HealthReporter` (`HealthSignal`: `Healthy`, `Unhealthy`, `Failed`); dropping the `ClusterConnection` tears its feeds and probe loop down. `ExecInteractivity` is the per-cluster exec-plugin policy passed with each connect. | `oxikube_ports::{connector, access}` |
| **SessionUpdate** | One change to one session (`Opened`, `StateChanged`, `CapabilitiesChanged`, `NamespaceChanged`, `ReadOnlyChanged`, `ColourChanged`, `Closed`), tagged with its `ClusterId`, on a bounded broadcast; a slow subscriber gets `SessionLagged` and re-reads. Not to be confused with `SessionEvent`, the state machine's input. | `oxikube_app::session` |
| **Catalog / CatalogEntry** | The list of every kubeconfig context Oxikube knows (the home screen). A `CatalogEntry` is one `ClusterContext` of the `ClusterSourcePort` (name, kubeconfig cluster and user names, source file, an optional `problem` when it names something the kubeconfig lacks) plus the user's marks: favourite and last-used time, kept in the `cluster_catalog` state table. Ordered favourites, then last used, then name. Reading it never touches a cluster. | `oxikube_app::catalog` |
| **ClusterColour** | A cluster's accent colour, sRGB written `#rrggbb` (hotbar dot, tab stripe, badges). | `oxikube_domain::colour` |
| **ClusterSessionState** | `Disconnected → Connecting → (AuthRequired) → Ready ↔ Degraded → Error`. Advanced by `SessionEvent`s; `SessionPhase` is the payload-free discriminant; a bad pair is an `InvalidTransition`. | `oxikube_domain::session` |
| **ConnectView / ConnectViewModel** | What a cluster tab shows while its session is not `Ready`: a spinner with the server for `Connecting`, the plugin's message with the cluster's exec policy and Retry for `AuthRequired`, a summary with expandable details for `Error`, and (as a banner over the content, not instead of it) "some data may be stale" for `Degraded`. `ConnectViewModel::of(state, info)` is the pure mapping; every text in it is redacted. Retry is `cluster::Reconnect`, Cancel is `cluster::CancelConnect`. | `oxikube_catalog_ui::connect` |
| **ExecPolicy** | The per-cluster `exec_interactivity` setting as the connect view words it: *Forbid* (`never`: a credential plugin may not prompt), *Ask* (`if_available`: it may use a terminal when one exists), *Allow* (`always`). Shown next to `AuthRequired`, with how to sign in outside the app when interaction is forbidden. | `oxikube_catalog_ui::connect` |
| **NamespaceSelection** | `All` or a `Set` of namespaces chosen in the UI. `NamespaceFavourites` is the user's pinned list. | `oxikube_domain::session` |
| **WatchScope** | Derived from a `NamespaceSelection` and a kind's `Scope`: `Cluster` or `Namespaces`; decides whether feeds are cluster- or namespace-scoped. | `oxikube_domain::session` |
| **NamespaceService** | Sets a session's `NamespaceSelection` and remembers it per cluster with the favourites and the namespace names the user typed (`NamespacePrefs`, `StatePort` kv `cluster/<id>/namespaces`, never settings). Lists namespaces for the selector; when the cluster answers `Forbidden` the list is the typed names (`NamespaceSource`). Runs the `namespace::Select` and `namespace::ToggleFavourite` commands. An empty selection is `All`; `0`-`9` select All or the first nine favourites. | `oxikube_app::session::namespaces` |
| **ScopeDelta** | What changes between two `WatchScope`s of a kind: namespaces whose feed starts, stops or stays, and whether the cluster-wide feed starts or stops. `{a, b}` to `{b, c}` starts `c`, stops `a`, keeps `b`. The `ResourceStore` re-scopes from it. | `oxikube_app::session::namespaces` |
| **NamespaceSelector** | The namespace dropdown of one cluster tab: trigger, search box, virtualised list of All / favourites / namespaces, digit keys. A view over the `NamespaceService`; it never opens feeds. | `oxikube_catalog_ui::namespaces` |
| **Feed** | A live stream of `DeltaBatch`es for one (cluster, gvk, scope): reflector, metadata-only, or Table API. Typed as `WatchFeed`. | `oxikube_ports::feed`; producers in `oxikube_kube::feed` (reflector and metadata-only variant: `ReflectorFeed`, E04-S02/S03) |
| **Watch budget / FeedStats** | Per-cluster limits on feeds (`max_feeds`) and held objects (`max_objects`), the idle grace period after which an unobserved feed is torn down, and the degrade of full feeds to metadata-only above `metadata_above` objects. `FeedRegistry` hands out `FeedLease`s (one per subscriber) and `SelectionLease`s (one feed per selected namespace); `FeedStats` is its counter snapshot (feeds, objects, events, restarts, bytes), `FeedVariant` what a feed carries (`Full`, `Metadata`, `Table`). | `oxikube_ports::feed_stats`; registry `oxikube_kube::budget` (E04-S13) |
| **FeedState** | Health of one feed: `Warming` (listing or relisting), `Live`, `Retrying` (backing off after a watch error), `Stopped`. Lets the session go `Degraded` while a feed retries. | `oxikube_kube::feed` |
| **Row action** | A command a resource table offers for an object (context menu, palette, key): a `RowActionSpec` (command, kinds, how an object becomes the command, bulk or not) registered in a `RowActionRegistry` and resolved against the `CommandBus` registry and the session's capabilities and read-only flag (`RowActions::actions_for` / `resolve`). Delete is the first; per-kind ones come with E12. | `oxikube_app::actions` |
| **Delete flow** | `DeleteFlow`: plans (`DeletePlan`) and runs a delete of one object or a selection. Each object is its own guarded `resource::Delete` (read-only check, confirmation tier by target, server dry run, audit with `Initiator::Ui`); one failure does not stop the rest and every object gets an `ItemStatus` (deleted, deleting, forbidden, not found, failed). Type-the-name is the object's name for one object and the cluster's context name for a selection. | `oxikube_app::actions` |
| **Delta / DeltaBatch** | One change in a feed (`Applied`, `Deleted`, `Restarted`) and a coalesced batch of them. Lives in ports, not the domain: it is transport. | `oxikube_ports::feed` |
| **Table / TableFeed** | Server-side Table API data (kubectl-identical columns incl. CRD printer columns) as `TableColumn`s and `TableRow`s. | `oxikube_ports::table`; producer `oxikube_kube::table` |
| **Drain** | Emptying a node of its pods like `kubectl drain`: plan (which pods are evicted, skipped as DaemonSet or mirror pods, or block the drain), cordon, evict with retry while a PodDisruptionBudget refuses, wait for each pod to go. Runs as a stream of `DrainProgress` and ends in a `DrainSummary`; configured by `DrainOptions`. | `oxikube_kube::algorithms` |
| **RolloutRevision** | One entry of a Deployment's rollout history: the revision number, the ReplicaSet that holds its template, the change cause and the images. `rollout undo` restores the template of one. | `oxikube_kube::algorithms` |
| **TableSource** | Whether a `Table`'s columns are the server's (`Server`) or the adapter's plain-JSON fallback (`Objects`, the server ignored the Table `Accept` header). | `oxikube_ports::table` |
| **ResourceStore** | App-side cache over one cluster session's feeds, keyed by (gvk, `FeedScope`), with sort/filter/index (name, namespace, label) and ref-counted subscriptions; the last subscriber's drop starts a grace period after which the feed is aborted. `ResourceStores` keeps one per connected session. | `oxikube_app::store` (E07-S01) |
| **CountState / CountsLease** | What the `ResourceStore` says about a kind's count (`Counted` with total and healthy, `Loading`, `NoAccess`, `OverBudget`, `Failed`, `NotWatched`). `ResourceStore::counts` only reads the caches' running tallies and starts no feed; a `CountsLease` keeps the feeds a view needs open through the normal subscribe path (so the watch budget decides). Health is `oxikube_domain::view::health_of`. | `oxikube_app::store::counts` (E07-S11) |
| **FeedScope** | The part of a `WatchScope` one feed covers: `Cluster` or one `Namespace`. A multi-namespace selection is served by one feed per namespace, so a namespace that stays selected keeps its feed. | `oxikube_app::store` |
| **FeedPolicy / FeedKind** | Which feed serves a kind (ADR 0006): `Full` reflector for core kinds, `Metadata` for bulky or sensitive ones (Secrets, ConfigMaps, Leases), `Table` for CRDs and unknown kinds. Table-driven, with per-kind overrides. | `oxikube_app::store` |
| **FeedBudget** | The hook a watch budget implements: `admit` (grant, degrade to a cheaper `FeedKind`, refuse) before the store opens a feed, `released` after it stops one. A refusal first evicts idle feeds. | `oxikube_app::store` |
| **StoreDelta / RowOp** | One item of a `Subscription` stream: the rows' change (a `Snapshot`, or coalesced `RowOp`s `Insert`/`Update`/`Remove` with positions in the subscriber's sorted list), the `FeedState` (`Warming`, `Ready`, `Retrying`, `Forbidden`, `Unauthorized`, `Failed`) and the Table columns when they change. Distinct from the transport `Delta` of `oxikube_ports::feed`. | `oxikube_app::store` |
| **ColumnProvider** | The one trait a table asks for a kind's `Column`s and an object's `Cell` in a column; `CoreColumns` (our catalogue of ~40 core kinds) and `TableColumns` (the server's Table columns) implement it. Cheap, synchronous, memoised per (kind, capabilities). | `oxikube_app::columns` (E07-S02) |
| **Column / ColumnId** | One table column: a stable `ColumnId` (the key column visibility and order persist under), title, `wide` flag (hidden by default, `kubectl -o wide`; Table `priority > 0`), alignment and `SortKind`. | `oxikube_app::columns` |
| **Cell / CellSort / Tone** | One table cell: display text, a typed sort key (`Int`, `Float`, `Quantity`, `Age`, `Time`, `Text`) so sorting never reparses text, and a `Tone` (neutral / ok / warn / error) the table maps to theme colours. `Cell::Pending` is a metrics hook with no value yet: shown blank, never `0`. | `oxikube_app::columns` |
| **TableState / Stale** | What a resource table is in, derived (purely) from the store's `FeedState`, the row count and the active filter: `Loading`, `Reconnecting`, `Empty`, `FilteredEmpty`, `Forbidden`, `Unauthorized`, `Failed`, or `Rows` (optionally `Stale`: refreshing, reconnecting, or the feed stopped). | `oxikube_resources_ui::table::states` (E07-S10) |
| **ApiWarning / WarningPort** | One `Warning:` response header of the API server (deprecated API, unknown field, admission note), redacted, broadcast per connection; the store shows each distinct (code, text) once per session. | `oxikube_ports::warnings`, `oxikube_kube::warnings` (E07-S10) |
| **LogService / LogSession / LogTarget** | The app's one service for streams of log lines. A `LogSession` is one open stream of a `LogTarget` (namespace, pod, optional container) over the `LogPort`: `Connecting`, `Streaming` (and `Reconnecting` while a broken stream waits to reopen, E08-S07), then `Ended` (`Completed`, `StreamClosed`, `Cancelled`, `PodFinished`, `ContainerFinished`, `PodReplaced`, `PodDeleted`) or `Failed`. Dropping the session cancels the read. A `LogReader` is its shared read-only view. | `oxikube_app::logs` (E08-S01) |
| **Reconnect / overlap / replacement (logs)** | A followed stream that breaks while its pod runs is **reconnected**: after a backoff with jitter (`logs.reconnect_retries` failures in a row, then `Failed` with a manual Reconnect), from a little before the last line received; the **overlap** the server replays is dropped by (server timestamp, text hash). A pod deleted or recreated by its controller is **replaced**: its session ends `PodReplaced` and "follow replacement" switches the view to the pod that took over (`find_replacement`, from the gone pod's `PodIdentity`). | `oxikube_app::logs::churn` (E08-S07) |
| **LogBuffer / LogEntry** | The bounded ring of a session's newest `logs.buffer_lines` lines. Every line has a seq (0, 1, 2, ... in stream order, never reused), so a line is found by index or by seq in O(1) and a range is a slice. Past the bound the oldest lines are dropped and counted: the "truncated" marker. | `oxikube_app::logs` |
| **LogDelta** | What changed in a session since its consumer last polled: the seqs appended, how many lines the consumer's window lost at the front, the first retained seq and the state. Computed per consumer at poll time, so deltas are batched at the consumer's cadence. Distinct from the transport `Delta` and the table's `StoreDelta`. | `oxikube_app::logs` |
| **LogView / LineWindow / Follow** | The log viewer (E08-S02): one pod's log as a workspace tab, opened by `pod::ViewLogs` ("View Logs" on a pod's row). Its **LineWindow** is the rows it shows (the "truncated" marker, the retained lines by seq, the state row); **Follow** is autoscroll, paused by a scroll up, with the "N new lines" pill counted by seq. Its options (range: tail / head / since 1m-1h, container, previous instance, wrap, timestamps) change through the `logs::*` commands; keys in the `LogView` key context. A **selection** (click, shift-click, drag) and **marks** (`m`, a gutter bar) are held by seq; `logs::Copy`, `logs::Save` (a `SaveDialog`, then the platform's save panel, written in chunks), `logs::Clear` (empties the local buffer, not the cluster's logs) act on them. | `oxikube_logs_ui::view`, `oxikube_logs_ui::export` |
| **LogFilter / LogMatcher / MatchIndex / search mode** | The search over a log (E08-S03). A **LogFilter** is the user's pattern: a regex, a case toggle, an inverse toggle (the lines without it). It compiles once per edit to a **LogMatcher**, whose `matches(&str)` is the one predicate the viewer and the agent's `get_logs` grep share. A **MatchIndex** is the sorted seqs of the matching lines of one session's ring buffer, kept up to date incrementally (new lines tested as they arrive, matches of dropped lines removed). The viewer's **search mode** is *highlight* (every line shown, matches painted, next / previous with a count) or *filter* (only the matching lines are rows). A window's **SearchMemory** keeps each target's search for the session. | `oxikube_app::logs::filter`, `oxikube_logs_ui::search` |
| **LogRecord / LogLevel / LevelChip** | JSON structured mode (E08-S05). A **LogRecord** is a log line that is a complete JSON object read into a normalised **LogLevel** (trace, debug, info, warn, error, fatal, unknown), a time, a message and its other fields; any other line is plain text. A **LevelChip** is one toggle of the viewer's level filter: the six levels plus `text` (plain lines and structured lines with no level); **LevelFilter** is the set of chips that are on. The service stores each line's level as it commits it (`LogEntry::level`). | `oxikube_app::logs::{parse, LevelFilter}`, `oxikube_domain::log` |
| **AggregateSession / AggregateSpec / AggregateView** | The multi-pod log (E08-S04): the lines of every pod a Deployment, StatefulSet, DaemonSet, ReplicaSet, Job or Service (its selector) or a typed label selector picks, merged by server timestamp into one `LogSession` (one ring of `logs.buffer_lines`). An `AggregateSpec` says what is read (namespace, object or selector, a narrowing selector, a container name); the `AggregateView` says which **sources** exist, what changed in the pod set and which sources are switched off. At most `logs.max_streams` containers are read at once. | `oxikube_app::logs::aggregate` (E08-S04) |
| **Source (log) / PodEvent / HiddenSources** | A **source** is one stream of an aggregate: one container of one pod (`SourceInfo`, with a `SourceId` assigned in the order the streams opened; it is the first tiebreak of equal timestamps). A **PodEvent** is a change of the pod set (`Added` for a pod that appears after the view opened, `Ended` for one that was deleted or whose streams all ended): the viewer's banner, and what reconnect-and-churn following (E08-S07) builds on. **HiddenSources** are the pods and containers the user switched off: they keep streaming and keep their lines in the buffer, the view filters them. | `oxikube_app::logs::aggregate` |
| **Reorder window** | How long an aggregate holds a line before committing it (`LogConfig::reorder_window`, 300 ms), so the lines of slower streams slot in before it: the merge is by server timestamp, then stream id, then position in the stream, and never reorders the lines of one pod. A line that arrives later than the window is committed at once, after what is there. | `oxikube_app::logs::aggregate` |
| **Pod gutter** | The fixed-width prefix of each line of a multi-pod log: the pod's short name (what its siblings' names do not share, plus `/container` when there are several) in a colour hashed from the pod name into the theme's `oxikube.log_sources` palette. | `oxikube_logs_ui::view::aggregate` |
| **LogExcerpt / ExcerptRequest** | A bounded, non-following read of a log for a reader that is not a viewer (E08-S09): the newest `tail` lines a `LogFilter` accepts, since a point in time, as one redacted text (`timestamp pod/container text`) within a byte budget, with **notes** that say what was left out (the tail, the size, a search limited to the newest lines, a timeout, failed streams, pods over `logs.max_streams`). The read behind the agent's `get_logs` tool and the `@logs` mention. | `oxikube_app::logs::excerpt` |
| **Send to agent / PendingContext / QueuedContext** | The viewer's action (`logs::SendToAgent`, key `a`, toolbar) that turns the selected lines (else the lines on screen) into a **ContextBlock** with its **ContextSource** (cluster, namespace, pod or workload, container, time span, line count; secrets masked) and queues it in the **PendingContext**, the small app service between the viewer and the agent panel: items wait (32 at most) until a `ContextConsumer` attaches, which receives them in order and then every later one. Nothing is persisted. | `oxikube_app::context`, `oxikube_logs_ui::view::agent` |
| **ResourceTable** | The generic, virtualised table of one kind in one cluster tab: rows from a `ResourceStore` subscription, cells from a `ColumnProvider`, multi-select by object identity, keyboard navigation in the `Table` key context. | `oxikube_resources_ui::table` (E07-S03) |
| **ColumnLayout / ColumnPrefs** | A kind's columns as the user arranged them (order, shown or hidden, widths, sort); saved per kind (not per cluster) under `table.columns.<group>/<Kind>`. | `oxikube_resources_ui::table` |
| **Filter / FilterExpr** | What the table's `/` bar means: `foo` (regex or substring on the name, case-insensitive), `!foo` (inverse), `-l k=v` (label selector) and `-f text` (fuzzy). Parsed by `oxikube_app::store::filter::parse`; an invalid one is an error shown in the bar, never an empty table. | `oxikube_app::store::filter` (E07-S04) |
| **Server-side selector** | The `-l` part of a filter: a label selector the subscription's feeds are keyed with, so the API server returns only the matches. Not the same as `StoreFilter::labels`, which filters cached objects. | `oxikube_app::store` (`FeedKey`, `Subscription::set_selector`) |
| **FilterBar** | The text field, error and `123 of 4,812` count of a table's filter. | `oxikube_resources_ui::filter` (E07-S04) |
| **KindSpec** | Per-kind registration: columns, detail renderer, actions, templates, sidebar section. | `oxikube_resources_ui::kinds` *(planned)* |

## Commands and safety

| Term | Meaning | Lives in |
|---|---|---|
| **Command** | A user/agent action: the `Command` payload enum, identified by a `CommandId` (`workload::Scale`) and described by `CommandMeta` (title, `CommandScope`, mutating, confirm tier, capabilities). Dispatched through the **CommandBus** (`CommandBus::dispatch(cmd, DispatchContext)`; handlers registered per crate into a `CommandRegistry`, each with its MCP tool stub). The id is also the keymap action and the MCP tool name. | `oxikube_domain::command`; bus in `oxikube_app::command_bus` |
| **Capability** | A flag for what a session/backend can do (mutate, exec, logs, portforward, helm, argo…). `Capabilities` is the set. | `oxikube_domain::command` |
| **MutationGuard** | The single pipeline every mutation passes: read-only check → confirmation tier → dry-run → execute → audit. It alone holds a `ResourceWriter` and hands it to a handler only inside a **Mutation** permit. A confirmation is a round trip: `Outcome::NeedsConfirmation` with a single-use `ConfirmationToken`, then a second dispatch carrying the `Confirmation`. Failing to audit fails the mutation closed. The writer inside a **Mutation** re-reads the read-only flag before every request, so a flow that outlives admission still stops. | `oxikube_app::guard`, `oxikube_app::audit` |
| **Risk / ConfirmTier** | Stories say "confirm low / medium / high". Mapping: **Low** → `Simple` (one-click confirm; may be skipped per session by setting), **Medium** → `Simple` naming the target and cluster, **High** → `TypeName`, **Irreversible** → `TypeName` + mandatory server dry-run diff. Reads never confirm. A read-only cluster refuses every tier before any request and records `AuditOutcome::Denied`; the guard returns the typed `DispatchError::ReadOnly { cluster, context }`, which maps to `ErrorKind::Forbidden` (`ErrorKind` has no `ReadOnly` variant). | `oxikube_domain::safety` |
| **Initiator** | `Ui / Command / Agent / Plugin` — who asked for a mutation. Defined in `safety`, re-exported from `audit`. | `oxikube_domain::safety` |
| **AuditRecord** | Who/what/where/when/outcome/initiator for a mutation (`AuditOutcome`: Succeeded, Failed, Denied, Cancelled). Never holds request bodies. Stored in SQLite through `StatePort`. | `oxikube_domain::audit` |

## Ports

A **port** is an async, object-safe trait in `oxikube_ports` that the app depends on and an adapter implements. Every fallible method returns `OxiResult`. Each port's module docs name its adapter; each has a `Fake*` in `oxikube_testkit::fakes`.

| Term | Meaning | Lives in |
|---|---|---|
| **ResourcePort** | `ResourceReader` + `ResourceWriter`. Only `MutationGuard` holds the writer half. | `oxikube_ports::resource` |
| **Forward** | One port-forward: a `ForwardSpec` (a pod or service `ResourceRef`, a remote `ForwardPort`, a local port and bind address, loopback by default) and its `ForwardStatus` (`Starting`, `Listening`, `TargetGone`, `Error`, `Stopped`). Run by the kube adapter, owned by `PortForwardManager` (E15). | `oxikube_domain::portforward`; adapter in `oxikube_kube::remote::portforward` |
| **DiscoveryPort / LogPort / ExecPort / PortForwardPort / TableFeedPort** | Data-plane access to a connected cluster. | `oxikube_ports::{discovery, log, exec, portforward, table}` |
| **ExecService / exec class** | `ExecService` (`oxikube_app::exec`) opens a shell (`open_shell`: each shell of the `terminal.exec_shells` chain, `bash` then `sh`, is probed with a quick exec and the first the container has opens, announced in the terminal's first line), an attach or a command in a pod container over `ExecPort`, and decides nothing about policy. The **exec class** is what the guard governs instead: the commands `pod::Shell`, `pod::Attach`, `pod::Exec` (`CommandMeta::exec`) are not mutations and take no confirmation, but are blocked on a read-only cluster unless `exec_in_read_only` allows them, are audited on every open (the record's `detail` names session kind, container and program, never content), and their tool stubs are unsafe, interactive and hidden from agents by default. A **container picker** (`oxikube_resources_ui::exec::ContainerPicker`) asks which container when the pod has several, the `kubectl.kubernetes.io/default-container` annotation or the last choice for the pod preselected; it runs before the command, so the audit names the container that opened. | `oxikube_app::exec`, `oxikube_app::guard`, `oxikube_resources_ui::exec` |
| **Node shell / debug container** | Two ways into a workload that has no shell of its own, both run by `oxikube_kube::remote::exec` on top of `ExecStreamPort` and handed out through `ExecPort::{node_shell, create_debug_container}`. A *node shell* is a privileged pod pinned to a node, exec'd into the node's namespaces and deleted when the shell ends, fails or is dropped (a labelled sweep removes leftovers). A *debug container* is an ephemeral container added to a running pod, then attached to. Both create objects, so they are guarded mutations. | `oxikube_kube::remote::exec::{node_shell, KubeExec::debug_container}` |
| **Kubeconfig source** | One entry of the user's list `kubeconfig.sources` in settings: `default` (what kubectl reads: `KUBECONFIG`, else `~/.kube/config`), a `file` read in place, or a `dir` of kubeconfig files. A pasted kubeconfig becomes a `file` source stored by Oxikube under `<config dir>/kubeconfigs/<name>.yaml` (owner-only). Each source shows its status: found with N contexts, missing, blank, or the problem with it, while the other sources keep loading. Managed with `kubeconfig::AddSource`, `kubeconfig::RemoveSource` and `kubeconfig::Reload` (ADR 0015). | `oxikube_app::sources`, `oxikube_ports::cluster_source` |
| **ClusterSourcePort / CloudDiscoveryPort** | Where cluster contexts come from: kubeconfig sources and cloud CLIs. | `oxikube_ports::{cluster_source, cloud}` |
| **MetricsPort / PromqlPort / HelmPort** | Optional read access: metrics-server, Prometheus, Helm releases. | `oxikube_ports::{metrics, promql, helm}` |
| **DescribePort** | `kubectl describe`-style text for one object, read-only, part of every connection's `ClusterPorts`. The result says which backend produced it (`DescribeSource::Native` or `KubectlFallback`). Backends: deskribe in process, or the `kubectl` binary, chosen by the `describe.backend` setting (`auto`, `native`, `kubectl`). Shown in the detail's Describe tab. | `oxikube_ports::describe`; adapters in `oxikube_describe` |
| **YAML tab** | The detail tab showing the object as read-only, highlighted YAML. `managedFields` are hidden until toggled; a Secret's values are always `(hidden)`; copy and save write exactly the displayed text. | `oxikube_resources_ui::detail::yaml` |
| **StatePort / SecretStorePort** | Durable local state (SQLite) and the only place secrets may be persisted (OS keychain). | `oxikube_ports::{state, secrets}` |
| **NotifierPort / UpdaterPort / CrashReporterPort / FsPort / ClockPort** | Platform services behind ports so tests can fake them. | `oxikube_ports::{notifier, updater, crash, fs, clock}` |
| **TerminalBackend / ExecPort** | `TerminalBackend` is the byte pipe the terminal element drives (`write`, `resize`, a pull-based `output_stream` of `BackendEvent::{Output, Exited, Error}`, an idempotent `kill`), the same for a local PTY, a pod exec/attach, a node shell and a debug container. `ExecPort` opens one (`exec`, `attach`, `create_debug_container`, `node_shell`, taking `ExecTarget` / `AttachTarget` / `DebugContainerSpec` / `NodeShellSpec` descriptors) and returns a `Box<dyn TerminalBackend>`; the last two mutate the cluster and are guarded by `ExecService` (E09-S09, E09-S10). `ExecStreamPort` is the lower, stream-level exec (`ExecSession`: stdin sink, stdout/stderr streams, resize sink, status) that `KubeExec` implements too; `SessionBackend` turns a session into a backend, and `KubeStream` is the cluster's backend built on it (it remembers its target, so "Reconnect" can reopen it). A connection that ends without the server's exit status is a *drop*, not an exit: the stream ends with `BackendEvent::Error` of kind `Network`, retryable, the cue to offer Reconnect. The element that paints a backend lives in `oxikube_terminal`. | `oxikube_ports::exec::{TerminalBackend, BackendEvent, ExecPort, ExecStreamPort, SessionBackend}`; impls: `oxikube_kube::remote::exec::{KubeExec, KubeStream}` (exec/attach/node shell/debug), `oxikube_terminal` (local PTY, display-only, E09-S02), `oxikube_argocd` (terminal WS); fakes `FakeTerminalBackend` and `FakeExecPort` in `oxikube_testkit::fakes::terminal` |
| **LocalPty / ClusterEnv** | `LocalPty` is the `TerminalBackend` over the user's shell on a PTY (`oxikube_terminal::backend::local`, E09-S02). `ClusterEnv` (context, optional namespace, the kubeconfig files to read it from) is what a cluster tab's terminal is opened with: `prepare` cuts the context out into a private temp kubeconfig and returns the shell variables (`KUBECONFIG`, `KUBE_CONTEXT`, `OXIKUBE_NAMESPACE`). `PATH` is never changed. | `oxikube_terminal::backend::local::{LocalPty, LocalPtyOptions, ClusterEnv}`; settings `terminal.shell`, `terminal.shell_args` |
| **TerminalElement / TerminalLink** | `TerminalElement` is the custom GPUI element that paints a `TerminalState` from its snapshot: cell backgrounds, selection, text runs, cursor (block, beam, underline; a hollow block when unfocused), underlines and strikethrough, in the theme's terminal colours (`TerminalPalette`). It keeps what it reuses between frames in a `TerminalElementState` (snapshot buffers, shaped rows by content hash). A **TerminalLink** is what is under the pointer while cmd (ctrl) is held: the cell's OSC 8 hyperlink, or a URL or file path found in the hovered line; cmd/ctrl-click dispatches `terminal::OpenLink` (`http`, `https`, `mailto`, `file` URLs, or an existing absolute path). | `oxikube_terminal::{element, open_link}` |
| **Key mapping / Bracketed paste / Mouse reporting** | The terminal's input encodings (`oxikube_terminal::mappings`, E09-S06, written from the xterm control sequence docs). **Key mapping** (`to_esc_str(keystroke, KeyMode)`) turns a keystroke with no text of its own into the bytes a program expects: `CSI X` / `SS3 X` cursor keys (application cursor keys mode, DECCKM), `CSI 1;m X` and `CSI n;m ~` modifier forms (`m` = 1 + shift 1 + alt 2 + ctrl 4), F1-F12, Ctrl-letter control codes, and **Alt as meta** (`ESC` + the key; `terminal.option_as_meta`, off on macOS where Option composes characters). Plain text and IME commits are not mapped: they go to the input handler as UTF-8. **Bracketed paste** wraps a paste in `ESC[200~ ... ESC[201~` when the process asked, stripping an embedded end marker so pasted text cannot end the bracket early; text with a line break asks for confirmation first (`terminal.confirm_multiline_paste`). **Mouse reporting** sends clicks, drags, motion and the wheel as SGR (1006), UTF-8 (1005) or legacy sequences while the process asked for them; Shift bypasses it for selection, and on the alternate screen the wheel otherwise sends cursor keys (alternate scroll). | `oxikube_terminal::mappings::{keys, paste, mouse}`; settings `terminal.option_as_meta`, `terminal.copy_on_select`, `terminal.confirm_multiline_paste` |
| **Composition (IME)** | The marked text an input method is composing (a reading, a dead key, a Hangul syllable): `TerminalState` implements GPUI's `EntityInputHandler`, the element paints the composition underlined at the cursor, and only the committed text is sent to the process, as UTF-8. The candidate window is placed from `bounds_for_range` (the cursor cell, set by the element each frame). | `oxikube_terminal::input::ime` |
| **TerminalView / BackendDescriptor / Terminal panel** | A **TerminalView** is one terminal tab: a workspace `Item` owning one process's `TerminalState` for as long as its tab lives, wherever the tab is dragged (centre panes or the bottom dock); closing it ends the process. Its **BackendDescriptor** says what it runs (a local shell with its program, directory, cluster and namespace; or a pod exec / attach with pod and container) and is all its tab saves: restoring or splitting starts a fresh process from it, never a replay, and no scrollback, title or environment value is stored. The **Terminal panel** is the side panel that anchors a cluster tab's bottom dock; terminal tabs share its tab group. `terminal::New` opens a shell for the shown cluster there, `terminal::Split` beside the active pane, `terminal::Close` closes the focused one. | `oxikube_terminal::view::{TerminalView, BackendDescriptor, TerminalPanel, TerminalViews}` |
| **TermGrid / TerminalState / TerminalSnapshot** | `TermGrid` is one terminal's emulator state: the cell grid with its scrollback (in memory only, `terminal.scrollback_lines`), modes, cursor, selection and title, and the VT parser that applies a process's output to it; the only wrapper around `alacritty_terminal`. `TerminalState` is the session as a GPUI entity: it feeds a `TerminalBackend`'s output into the grid on tokio, sends input and the emulator's replies back, and wakes its view at most once per frame. `TerminalSnapshot` is one frame's copy of what is visible, which the element paints without holding the grid. A **GridPoint** addresses a cell of the whole grid: line 0 is the top of the live screen, negative lines are scrollback. | `oxikube_terminal::{grid, state}` |

| Term | Meaning | Lives in |
